# 第 4 课 · 状态提升与组件通信

## 学习目标
完成本课后，你应该能够：
1. 说清 React 的单向数据流铁律：props 向下流，事件向上报。
2. 判断"某个 state 应该放在哪个组件"——放在所有需要它的组件的最近公共父组件。
3. 把一个子组件里的 state 提升（Lift Up）到父组件，实现兄弟组件联动。
4. 写出"受控到父级"的输入框：value 来自 props，onChange 调用父组件的回调。
5. 区分"有状态的容器组件"和"只吃 props 的纯展示组件"。

## 核心概念

### 单向数据流
React 中数据只能沿一个方向流动：

```
父组件 state ──props──▶ 子组件显示
   ▲                      │
   └──────onChange 回调────┘ 用户输入/事件向上报
```

子组件永远不直接修改 props（props 是只读的！），它想"改数据"，只能调用父组件传下来的函数，请父组件去改自己的 state。

### 状态提升（Lifting State Up）
两个组件需要共享数据时，把 state 放到它们的**最近公共父组件**。本课的温度转换器：摄氏输入框和华氏输入框是兄弟，它们共享同一个温度，所以温度 state 不能放在任何一边，必须放在父组件 `Lesson4` 里。

### 只存一个真相来源
温度转换器里我们只存摄氏度一个值（真相来源），华氏度是它的**派生值**，渲染时现算：

```jsx
const [celsius, setCelsius] = useState('25')
const fahrenheit = celsius === '' ? '' : String((Number(celsius) * 9) / 5 + 32)
```

这与第 2 课"派生数据不进 state"的结论一脉相承：存两份必然不同步，派生一份永远一致。

## 代码导读

### src/components/lesson4/TemperatureInput.jsx
一个"受控到父级"的输入框。注意它**没有一行 useState**：

- `temperature`（值）和 `onTemperatureChange`（上报回调）全部来自 props；
- `scale` 决定标签显示"摄氏度"还是"华氏度"，这样一个组件就能复用两次。

关键一行：

```jsx
<input value={temperature} onChange={handleChange} />
```

`value` 来自父组件 → 输入框显示什么完全由父组件决定；`onChange` 只做 `onTemperatureChange(e.target.value)`，即"把新值报给父组件"，自己不存储、不换算。换算逻辑放在父组件，因为只有父组件同时认识两个输入框。

### src/components/lesson4/BoilingVerdict.jsx
纯展示组件的典型：没有 state、没有事件，`celsius >= 100` 就显示"水会沸腾"，否则"水不会沸腾"。空输入时不给结论，避免页面一打开就出现误导性文字。这类组件极易复用与测试。

### src/pages/Lesson4.jsx
父组件（容器），数据与逻辑全在这里：

- `const [celsius, setCelsius] = useState('25')` —— 唯一的真相来源。用字符串存，是为了让输入框能显示 `"3."`、`"3.0"` 这类输入中间态（数字会丢掉末尾的小数点）。
- `handleTemperatureChange(scale, value)` —— 两个输入框共用一个处理函数：摄氏输入原样存，华氏输入先换算回摄氏再存。
- `fahrenheit` —— 每次渲染由 `celsius` 现算的派生值，换算结果保留两位小数精度。
- 页面还包含一个 **❌ 错误示范** 小节（`BrokenInputs`）：两个输入框各拿到一份写死的初始值（25°C 和 77°F）且回调为空函数，你在一边输入另一边毫无反应——这就是 state 留在子组件里的下场，也是我们必须提升的理由。

### src/pages/lesson4.css
本课专属样式：输入框排版与沸腾结论的红/蓝配色。公共样式类（.card、.row、.hint 等）复用 App.css，不重复定义。

## 动手试一试
1. **公斤/磅双输入**：仿照温度转换器，做一个公斤（kg）↔ 磅（lb）双输入框（1 kg = 2.20462 lb）。提示：state 只存公斤，磅做派生值；换算系数不同但结构一模一样。
2. **能被父组件重置的计数器**：把第 1 课的 Counter 改造成受控版本——计数值存在父组件里，Counter 只显示数值并把点击上报给父组件；父组件再放一个"全部归零"按钮，能同时重置页面上两个 Counter。体会"没有提升就做不到的事"。
3. **温度转换器加单位切换**：给父组件加一个 state 记录"以哪个输入框为准"，让换算结果保留更多小数（如 4 位），再想想精度该存进 state 还是现算。

## 易错点
1. **受控组件里又写了本地 state**：子组件一边 `value={props.value}` 一边自己 `useState` 存一份，出现两个真相来源。现象：输入框"跳字"或两个兄弟不同步。原因：state 和 props 抢同一份数据的解释权。
2. **用 `Number` 存输入框的值**：输入 `"3."` 时 `Number("3.")` 得 3，小数点立刻消失，用户没法输入小数。原因：字符串到数字的转换会丢掉输入中间态。正解：state 存字符串，只在计算时转数字。
3. **忘记空输入的分支**：华氏框清空后 `(NaN - 32) * 5 / 9` 得 NaN，页面显示 NaN。原因：没对 `value === ''` 特判。任何"输入 → 数字"的换算都要先处理空串。
4. **精度失控**：华氏 77 转摄氏得 `25.555555...`，再转回华氏可能漂移。正解：换算后用 `toFixed(2)` 保留两位再 `Number` 回数字，去掉多余尾零。
5. **子组件直接改 props**：写 `props.value = 5` 或在子组件里 `onChange` 里偷偷改对象属性。React 要么报错要么静默不同步——props 只读是铁律，改数据请上报给父组件。

## 自测题
1. 两个兄弟组件要共享数据，有哪些办法？React 官方推荐哪种？
2. 为什么本课只存摄氏度一个 state，而不分别存摄氏和华氏两个 state？
3. TemperatureInput 里没有 useState，那它的"值"从哪来、"变化"往哪去？
4. 为什么温度 state 用字符串而不是数字存储？

<details><summary>参考答案</summary>

1. 状态提升到最近公共父组件（推荐）；此外还有 React Context（跨多层传递）、外部状态库（Redux 等）。但第一步永远是考虑提升。
2. 两个 state 就是两个真相来源，必须双向同步，一旦换算有精度误差就会互相"抖动"；只存一个，另一个做派生值，永远一致。
3. 值来自父组件的 props（`temperature`），变化通过回调（`onTemperatureChange`）上报给父组件，由父组件 setState 后重新渲染把新值发回来。
4. 数字会丢掉输入中间态：输入 `"3."` 转成数字 3 后再写回输入框，小数点消失，用户无法输入小数。字符串只在计算那一刻转成数字。
</details>
